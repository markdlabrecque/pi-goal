Goal pursuit in Pi

Approved for implementation. The user accepted the plan and its proposed defaults. No implementation starts in this step.

Why · 2 requests Claude code has a goal command that has the harness pursue a goal until completion. Does Pi have a similar command? If not, would this make more sense to implement as a skill or a Pi extension? Ok let’s add a new extension called pi-goal. Create a plan doc inside that folder to start

The user can start one goal in each session.

The command saves the goal before it starts work.

Pi continues when work remains and the goal is active.

The extension requests continuation only at the final actionable boundary.

Pi 1.5.2 documents this hook in docs/extensions.md:663-695. Do not use agent_end as the final boundary. Pi can still retry or compact after that event.

Completion requires a report against the acceptance criteria.

Approved decision: Completion requires an evidence report for each acceptance criterion. The first version does not require an extension-run test command. The default supports goals without a test command. A report tool cannot prove arbitrary real-world success. Test commands need explicit user approval.

Stops and limits prevent automatic work without an end.

Approved decision: Each goal starts with a limit of 10 automatic continuations. Count extra runs, not individual tool calls. The user can change the limit with /goal limit.

Tests cover stops before the extension can start more work.

Session entries hold the goal state and its evidence.

Proposed files under extensions/pi-goal/: package.json, index.ts, state.ts, policy.ts, tools.ts, tests/policy.test.ts, tests/lifecycle.test.ts, README.md, and tsconfig.json. The count excludes these plan files. Match the local extension package format. Confirm the installed SDK types before implementation. Use an isolated fixture to test discovery without a global settings change.

This plan adds no code and changes no Pi settings.
